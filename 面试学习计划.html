GlobalExceptionHandler.java — 全局异常处理（面试高频考点！）
@RestControllerAdvice // 拦截所有Controller抛出的异常 public class GlobalExceptionHandler { @ExceptionHandler(BizException.class) public ApiResponse handleBizException(BizException e) { // 业务异常 → 统一返回 ApiResponse.error return ApiResponse.error(e.getCode()); } // 面试问：为什么要有全局异常处理？ // 答：避免每个接口都写 try-catch，统一错误响应格式 // 防止异常堆栈信息泄露给客户端 }
⚠️
面试必问：软删除和硬删除的区别？
答：软删除只是将 is_active 改为 false，数据还在数据库，可以恢复，适合需要审计记录的场景。硬删除是真正从数据库删除，不可恢复，适合彻底清理数据的场景。你们项目的 materials 和 classes 表都用了软删除。

Day 2 · JWT认证 & Spring Security

你们项目最核心的安全机制，面试必考

🎯
你们项目的认证方案很有亮点：学生用 JWT + session表双重校验，管理员用 密码指纹校验，这在面试中是加分项！
Step 1 · 微信获取openid
微信云托管自动注入 X-WX-OPENID
微信小程序通过云托管调用时，平台自动在请求头中注入 X-WX-OPENID，后端直接读取，无需自己请求微信接口换取openid。
Step 2 · 学生绑定信息
POST /api/auth/bind — 绑定学号姓名
用openid匹配 students 表，找到对应学生后生成JWT token，同时把 token 的 SHA-256 哈希存入 sessions 表。
Step 3 · 每次请求验证
JwtAuthFilter 拦截验证
解析JWT → 验证签名和过期 → 计算token的SHA-256哈希 → 与数据库sessions表比对 → 通过后设置SecurityContext。
Step 4 · 权限控制
ROLE_STUDENT / ROLE_ADMIN 角色区分
JWT中携带role字段，学生只能访问练习相关接口，管理员可访问 /api/admin/** 所有管理接口。
JWT三段式结构 — 你们项目的Payload内容
// JWT = Header.Payload.Signature // 学生Token的Payload: { "sub": "123", // studentId "uid": 123, "role": "STUDENT", "iat": 1700000000, // 签发时间 "exp": 1700604800 // 过期时间（7天） } // 管理员Token的Payload（多了密码指纹！）: { "sub": "ADMIN:12", // ADMIN前缀区分 "role": "ADMIN", "ph": "a3f2bc...", // 密码Hash的指纹 → 改密码后旧token自动失效 "exp": 1700604800 }
JwtAuthFilter.java — 核心过滤器逻辑（来自你们真实代码）
public class JwtAuthFilter extends OncePerRequestFilter { @Override protected void doFilterInternal(HttpServletRequest req, ...) { String auth = req.getHeader("Authorization"); if (auth == null || !auth.startsWith("Bearer ")) { chain.doFilter(req, resp); // 没token，放行（由Security配置决定后续） return; } String token = auth.substring("Bearer ".length()); Claims claims = jwtUtil.parse(token); // 验证签名+解析 String sub = claims.getSubject(); if (sub.startsWith("ADMIN:")) { // 管理员：验证密码指纹 String phInToken = claims.get("ph", String.class); String phNow = sha256Hex(admin.getPasswordHash()); if (!phNow.equals(phInToken)) { write401(resp, "ADMIN_TOKEN_REVOKED"); return; } } else { // 学生：查session表验证token_hash String dbHash = sessionMapper.getTokenHash(studentId); if (!dbHash.equals(sha256Hex(token))) { write401(resp, "SESSION_INVALID"); return; } sessionMapper.touch(studentId); // 更新最后活跃时间 } // 认证通过，设置SecurityContext SecurityContextHolder.getContext().setAuthentication(authentication); chain.doFilter(req, resp); } }
🛡️ SecurityConfig关键配置 必背
  • csrf().disable() — API无状态，不需要CSRF防护
  • formLogin().disable() — 关闭表单登录
  • sessionManagement().disable() — 无状态模式
  • antMatchers(...).permitAll() — 白名单放行
  • anyRequest().authenticated() — 其他需登录
  • addFilterBefore() — 注册JWT过滤器
❓ JWT常见面试问题 重点
  • JWT和Session有什么区别？
  • JWT如何实现登出/主动失效？
  • Token泄露了怎么办？
  • 为什么用HS256而不是RS256？
  • OncePerRequestFilter是什么？为什么用它？
  • BCrypt密码加密的原理？
🔥
你们项目的JWT亮点（重点说！）：普通JWT一旦签发就无法主动失效，但你们在数据库加了 sessions 表存储 token_hash，登出时删除记录，即使token未过期也无法通过验证。这解决了JWT最大的缺点！

MyBatis Mapper示例 — 你们项目的Mapper写法
@Mapper public interface SessionMapper { // 注解方式（简单SQL） @Select("SELECT token_hash FROM sessions WHERE student_id = #{studentId}") String getTokenHash(@Param("studentId") long studentId); @Update("UPDATE sessions SET last_touched_at = NOW() WHERE student_id = #{studentId}") void touch(@Param("studentId") long studentId); // XML方式（复杂SQL，写在 resources/mapper/SessionMapper.xml） void upsertSession(@Param("studentId") long studentId, @Param("tokenHash") String tokenHash); }
🔧 MyBatis核心知识点 必备
  • @Mapper — 声明这是MyBatis的Mapper接口
  • @Select/@Insert/@Update/@Delete — 注解写SQL
  • XML Mapper — 复杂SQL、动态SQL写这里
  • ResultMap — 处理字段名和属性名不一致
  • 动态SQL：<if><foreach><where> 标签
  • #{}防SQL注入 vs ${}不防（面试必问！）
💾 数据库设计要点 重点
  • 外键设计：attempts.studentId → students.id
  • 索引：openid/studentNo这种查询字段必须加索引
  • 事务：练习提交时更新能力值+记录答案需原子性
  • 软删除：is_active字段，不真正删记录
  • @Transactional注解：方法级事务控制
  • ACID：原子性/一致性/隔离性/持久性
⚠️
#{} vs ${} 的区别（面试超高频！）：
#{} 是预编译参数，MyBatis会把它转成JDBC的 ?，能防止SQL注入。
${} 是直接字符串拼接，有SQL注入风险，只用于表名、列名等无法预编译的地方。你们项目里的SQL都用的 #{}，这是正确做法。

Day 4 · IRT算法亮点 & 模拟面试

掌握项目最大亮点，冲刺面试最后一天

⭐
这是你面试最大的加分项！大多数同学的项目是简单CRUD，但你们实现了自适应能力评估系统，基于IRT理论，面试官一定会感兴趣，好好准备这个的介绍。
IRT能力值算法 — AbilityEstimator核心逻辑
// IRT = Item Response Theory（项目反应理论） // 核心思想：根据题目难度和学生答对率，动态估计学生能力值 public class AbilityEstimator { static final double THETA_MIN = 1.0; // 能力值范围 1~10分 static final double THETA_MAX = 10.0; static final double BETA = 1.0; // 题目区分度 static final double STEP_CAP = 0.8; // 单次更新最大步长（防跳跃） // 核心公式：sigmoid函数（答对概率） // p = 1 / (1 + e^(-(theta - difficulty) / beta)) // theta越高，难题答对率越高 // 贝叶斯更新： // prior: 学生当前能力值theta和方差var // likelihood: 本次答题结果 // posterior: 牛顿法迭代更新新的theta }
📊 如何向面试官介绍IRT算法 亮点
  • 背景：传统测试不能反映真实能力（刷题可刷高分）
  • IRT：根据题目难度系数动态计算能力值theta
  • 自适应：能力值高 → 推荐更难的材料
  • 贝叶斯更新：每次答题后更新theta和方差
  • 防刷分：只有首次练习才更新能力值
  • 10分量表：直观展示学生水平
🐳 Docker部署 了解
  • Dockerfile：定义镜像构建步骤
  • 基础镜像：eclipse-temurin:17-jre-alpine
  • 暴露端口：80（微信云托管标准）
  • 环境变量：MYSQL_ADDRESS/USERNAME/PASSWORD
  • 面试问：为什么要容器化？→ 环境一致性
  • 微信云托管：无需自己维护服务器

面试问答速查

基于你们真实项目的标准答案，照着说就行

Q1介绍一下你们的项目
我们做的是一个微信小程序端的智能听力测试系统，后端基于Spring Boot开发。系统主要面向大学英语听力教学场景，学生通过微信小程序做听力练习，系统会根据答题情况自动评估学生的能力水平。
核心亮点是实现了基于IRT理论的自适应能力评估算法，能够根据题目难度和学生的答对率，用贝叶斯方法动态更新学生的能力值（1-10分），并据此推荐难度匹配的练习材料。技术栈是Spring Boot + Spring Security + MyBatis + MySQL，部署在微信云托管上。
Q2你们的用户认证是怎么做的？
我们用了JWT无状态认证，因为前端是微信小程序，不适合用传统Session。具体流程是：微信云托管会自动注入用户的openid到请求头中，后端用openid匹配学生信息，验证通过后生成JWT token返回给前端，有效期7天。
但纯JWT有个问题：签发后无法主动失效。我们的解决方案是在数据库加了sessions表，存储token的SHA-256哈希。每次请求除了验证JWT签名，还要查sessions表确认哈希匹配，这样登出时删除session记录，旧token就立即失效了。另外管理员token还带了密码的指纹hash，改密码后旧token自动作废。
Q3Spring Security是怎么配置的？
我们继承WebSecurityConfigurerAdapter，关闭了CSRF（无状态API不需要）和Session管理，配置了白名单接口（登录、绑定、班级列表等公开接口）可以不带token访问，其余接口都需要认证。注册了一个自定义的JwtAuthFilter，继承OncePerRequestFilter，确保每个请求只过滤一次，在filter中解析JWT并设置SecurityContext。
Q4MyBatis和Hibernate/JPA的区别？你们为什么选MyBatis？
MyBatis是半自动ORM，SQL由开发者自己写，灵活可控；JPA/Hibernate是全自动ORM，框架生成SQL，开发效率高但复杂查询难控制。
我们选MyBatis因为项目有比较复杂的多表联查（比如获取练习记录时要关联attempts、questions、materials多张表），用MyBatis的XML写SQL更直观可控。而且能精确控制查询的字段，避免全量查询造成性能浪费。
Q5你们数据库表是怎么设计的？
一共12张表。核心关系是：students和materials是多对多关系，通过attempts表做关联，记录每次练习的过程数据和能力值变化。classes和students是一对多，materials和questions是一对多，questions和question_options是一对多。
设计上用了软删除（is_active字段），materials和classes都支持激活/禁用状态，数据不会真正删除便于审计。sessions表用于JWT的主动失效机制，student_ability_state表单独追踪每个学生的能力值方差，避免每次都重新计算。
Q6项目遇到了什么难点？怎么解决的？
主要有两个难点。第一个是IRT能力值计算，普通的百分比正确率无法区分难题做对和简单题做对的价值差异。我们引入了贝叶斯+牛顿法的迭代更新，每次答题后根据题目难度系数动态调整theta，同时用方差追踪估计的置信度。
第二个是JWT主动失效问题，纯JWT签发后7天内都有效，如果token泄露无法及时处理。我们通过sessions表的token_hash机制解决了这个问题，并且管理员的密码指纹机制也保证了改密码后旧token立即失效。
Q7什么是Spring Boot自动配置？
Spring Boot的@SpringBootApplication注解包含了@EnableAutoConfiguration，它会扫描classpath下所有jar包里的META-INF/spring.factories文件，根据条件注解（@ConditionalOnClass等）自动装配Bean。比如引入mysql-connector和mybatis-spring-boot-starter后，Spring Boot会自动创建DataSource和SqlSessionFactory，不需要手动配置。
这就是为什么你们的pom.xml里加了几个依赖，在application.yml里配几行数据库连接就能用了，不需要写大量XML配置，这正是Spring Boot相比传统Spring的优势。
Q8事务是什么？什么时候要用？
事务保证一组数据库操作要么全部成功，要么全部回滚，符合ACID原则（原子性、一致性、隔离性、持久性）。Spring中用@Transactional注解声明事务方法。
在我们项目中，学生提交练习时需要：①记录answers、②更新attempt状态、③更新student的theta能力值、④更新student_ability_state的方差——这4个操作必须原子性完成，任何一步失败都要全部回滚，否则会出现能力值更新了但答案没记录的数据不一致情况。所以submitAndUpdate方法加了@Transactional。
