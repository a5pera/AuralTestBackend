Spring Boot 框架基础

项目的"骨架"，让你几乎不需要配置就能跑起来
💡
Spring Boot 是什么？ 它是 Spring 框架的快速启动版本，帮你省掉大量繁琐配置，专注写业务逻辑。就像"方便面"版的 Spring。
启动入口：WxCloudRunApplication.java
@SpringBootApplication   // 这一个注解顶三个注解，开启自动配置
public class WxCloudRunApplication {
    public static void main(String[] args) {
        SpringApplication.run(WxCloudRunApplication.class, args);
    }
}
常用注解速查
注解作用用在哪
@SpringBootApplication启动类标记 + 自动配置启动类
@RestController标记为 REST 接口控制器Controller 类
@RequestMapping定义接口路径前缀Controller 类
@GetMapping处理 GET 请求Controller 方法
@PostMapping处理 POST 请求Controller 方法
@Service标记为服务层组件Service 实现类
@Autowired自动注入依赖需要注入的字段
@Component通用组件，由 Spring 管理工具类等
@Configuration配置类标记配置类
@Bean声明一个 Bean 交给 Spring 管理配置类中的方法
接口示例：AuthController.java
@RestController
@RequestMapping("/api/auth")
public class AuthController {

    @Autowired
    private AuthService authService;   // 自动注入业务层

    @PostMapping("/login")              // POST /api/auth/login
    public ApiResponse login(@RequestBody LoginRequest req) {
        return authService.login(req);
    }
}

MVC 三层架构

职责分离，代码清晰，便于维护
💡
为什么要分层？ 把"接收请求"、"处理逻辑"、"操作数据库"分开，修改一层不影响其他层，就像工厂里的流水线各司其职。
前端请求
→
Controller
接电话
→
Service
干活
→
DAO/Mapper
查数据库
→
MySQL
层次目录职责本项目示例
Controllercontroller/接收请求、返回响应AuthController, PracticeController
Serviceservice/impl/处理业务逻辑AuthServiceImpl, MaterialServiceImpl
DAOdao/操作数据库StudentMapper, AttemptMapper
Modelmodel/数据库表对应的 Java 类Student, Material, Question
完整调用链示例：学生登录
// 1. Controller 层 —— 接收请求
@PostMapping("/login")
public ApiResponse login(@RequestBody LoginRequest req) {
    return ApiResponse.success(authService.login(req));
}

// 2. Service 层 —— 处理业务逻辑
public AuthData login(LoginRequest req) {
    Student student = studentMapper.findByOpenid(req.getOpenid());
    String token = jwtUtil.issueToken(student);
    return new AuthData(token, student);
}

// 3. DAO 层 —— 查询数据库
@Mapper
public interface StudentMapper {
    Student findByOpenid(String openid);
}

MyBatis 注解示例
@Mapper  // 标记为 MyBatis Mapper，Spring 会自动实现它
public interface StudentMapper {

    @Select("SELECT * FROM student WHERE wechat_openid = #{openid}")
    Student findByOpenid(String openid);

    @Insert("INSERT INTO student(name, wechat_openid) VALUES(#{name}, #{openid})")
    void insert(Student student);

    @Update("UPDATE student SET theta = #{theta} WHERE id = #{id}")
    void updateTheta(Student student);
}

JWT + Spring Security 身份认证

保护接口安全，确保只有登录用户才能访问数据
💡
两个东西的分工：
• Spring Security = 保安系统，控制哪些接口需要登录才能访问
• JWT = 通行证，登录后颁发给用户，请求时出示证明身份
JWT 认证完整流程
① 用户登录
发送微信 openid
→ AuthController.login()
↓
② 验证身份
查数据库核对
→ AuthServiceImpl
↓
③ 签发 Token
返回 JWT 字符串
→ JwtUtil.issueToken()
↓
④ 后续请求
Header 带 Token
→ JwtAuthFilter 拦截验证
↓
⑤ 放行/拒绝
合法则放行
→ SecurityConfig 规则
JWT Token 的结构（了解即可）
// JWT = Header.Payload.Signature，三段用 . 连接
eyJhbGciOiJIUzI1NiJ9          ← Header（加密算法）
.eyJzdWIiOiIxMjMifQ            ← Payload（用户信息，可解码但不要存敏感数据）
.SflKxwRJSMeKKF2QT4fwpMeJf36  ← Signature（签名，防篡改）
关键安全文件
文件功能
security/JwtUtil.java生成 Token（issueToken）/ 解析 Token（parse）
security/JwtAuthFilter.java每次请求都会经过，自动验证 Header 中的 Token
config/SecurityConfig.java配置哪些 URL 需要认证，哪些公开访问
config/JwtProperties.java从 application.yml 读取 JWT 密钥和有效期
application.yml 中的 JWT 配置
# 7天过期（604800秒）
jwt:
  secret: "AURAL_TEST_BACKEND_SECRET_CODE_32_CHARS_MIN_12345"
  ttlSeconds: 604800

DTO 数据传输对象

规范接口数据格式，隔离数据库层与接口层
💡
DTO 解决什么问题？ 数据库的 Student 表有很多字段（包括密码、内部ID等），但前端不需要全部，DTO 只暴露前端需要的字段，更安全、更清晰。
DTO vs Model 对比
// Model（数据库实体）—— 完整字段
public class Student {
    private Long id;
    private String studentNo;
    private String name;
    private String wechatOpenid;   // 不应该返回给前端！
    private Double theta;           // 内部算法字段
    private Long classId;
}

// DTO（传输对象）—— 只给前端需要的
public class StudentInfoDTO {
    private Long id;
    private String name;
    private String college;
    private String className;
}
项目 DTO 目录结构
DTO 分类主要文件用途
认证 auth/StudentInfoDTO, AuthData, BindRequest登录/绑定请求与响应
练习 practice/PracticeSubmitRequest, PracticeAttemptDTO提交答案、查看记录
题目 quest/UploadMaterialRequest, MaterialDetailDTO上传材料、获取题目详情
管理 admin/ClassStudentDTO, LeaderboardResponse班级管理、排行榜

统一异常处理

系统出错时优雅响应，而不是给用户看报错页面
⚠️
没有异常处理会怎样？ 系统报错时直接把 Java 堆栈信息暴露给用户，既不安全又不友好。统一异常处理让你能优雅地返回有意义的错误信息。
GlobalExceptionHandler.java —— 全局异常拦截器
@ControllerAdvice  // 监听全局异常
public class GlobalExceptionHandler {

    // 捕获业务异常（比如"学生不存在"）
    @ExceptionHandler(BizException.class)
    public ResponseEntity<?> handleBizException(BizException e) {
        return ResponseEntity.badRequest()
            .body(ApiResponse.fail(e.getMessage()));
    }

    // 捕获认证异常（Token 无效等）
    @ExceptionHandler(ApiException.class)
    public ResponseEntity<?> handleApiException(ApiException e) {
        return ResponseEntity.status(e.getStatus())
            .body(ApiResponse.fail(e.getMessage()));
    }
}
自定义异常类
异常类用途
BizException业务逻辑异常（如"学号已被绑定"）
ApiException接口层异常（如 401 未授权、404 未找到）

统一响应格式

所有接口返回同样结构的 JSON，前端处理更方便
ApiResponse.java —— 统一返回包装类
public class ApiResponse<T> {
    private int code;       // 状态码：200成功，其他为失败
    private String message; // 提示信息
    private T data;         // 实际数据

    public static <T> ApiResponse<T> success(T data) { ... }
    public static ApiResponse<?> fail(String message) { ... }
}
前端收到的 JSON 格式
// 成功
{
  "code": 200,
  "message": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "name": "张三"
  }
}

// 失败
{
  "code": 400,
  "message": "学号不存在，请先联系老师录入",
  "data": null
}

配置管理（application.yml）

用环境变量管理敏感配置，安全且易于部署
application.yml 完整配置解析
# 服务端口
server:
  port: 80

spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    # ${MYSQL_ADDRESS} 从环境变量读取，不把地址写死在代码里
    url: jdbc:mysql://${MYSQL_ADDRESS}/${MYSQL_DATABASE:arual_test}
    username: ${MYSQL_USERNAME}
    password: ${MYSQL_PASSWORD}

# JWT 配置
jwt:
  secret: "AURAL_TEST_BACKEND_SECRET_CODE_32_CHARS_MIN_12345"
  ttlSeconds: 604800    # 7天 = 7×24×3600

# MyBatis Mapper 文件路径
mybatis:
  mapper-locations: classpath*:mapper/*Mapper.xml
⚠️
为什么用 ${ENV_VAR}？ 数据库密码这类敏感信息不能写死在代码里，否则上传 Git 后所有人都能看到。用环境变量在服务器上单独配置，更安全。
配置类绑定示例：JwtProperties.java
@Component
@ConfigurationProperties(prefix = "jwt")  // 自动读取 yml 中 jwt.* 配置
public class JwtProperties {
    private String secret;      // 对应 jwt.secret
    private long ttlSeconds;    // 对应 jwt.ttlSeconds
}

Lombok —— 代码简化神器

用注解自动生成重复代码，让实体类干净简洁
Lombok 注解 vs 手写代码对比
// 不用 Lombok —— 又臭又长
public class Student {
    private Long id;
    private String name;

    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    // ... toString, equals, hashCode
}

// 用 Lombok —— 简洁优雅
@Data            // 自动生成所有 getter/setter/toString/equals
@Builder         // 支持链式构建：Student.builder().name("张三").build()
@NoArgsConstructor  // 无参构造
@AllArgsConstructor // 全参构造
public class Student {
    private Long id;
    private String name;
}
常用 Lombok 注解速查
注解作用
@Data= @Getter + @Setter + @ToString + @EqualsAndHashCode
@Builder生成建造者模式，支持链式调用
@NoArgsConstructor生成无参构造函数
@AllArgsConstructor生成全参构造函数
@Slf4j自动注入日志对象 log，可直接用 log.info()
