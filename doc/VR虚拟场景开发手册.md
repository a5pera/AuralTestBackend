# 《AI 情境听力教学系统设计与开发》VR 虚拟场景开发手册

## 1. 文档目的

本文档用于说明《AI 情境听力教学系统设计与开发》中“智能情境资源库”的场景化建设方案，以及其与 VR 虚拟场景、听力材料、音频资源、题库和学生练习流程之间的关系。

需求文档中提出“基于 Seq2Seq 模型与 WaveNet 语音合成技术，开发包含‘学术讲座+商务谈判’的智能情境资源库”。结合本项目实际实现，智能情境资源库在系统中主要落地为听力材料库，即后端 `materials`、`audio_assets`、`questions`、`question_options` 等数据模型承载的资源集合。每一份听力材料可视为一个情境任务单元，包含场景类型、听力文本、音频、难度、题目、选项和标准答案。

本项目当前未直接集成 WaveNet 语音合成服务，而是通过音频资源登记接口接入已给定或外部生成的听力音频。该设计保留了后续接入 WaveNet、神经 TTS 或其他语音生成服务的扩展空间。

## 2. 场景资源库定位

智能情境资源库不是单纯的音频文件集合，而是由“场景背景 + 听力材料 + 音频资源 + 练习任务 + 难度标签 + 学习反馈”组成的教学资源库。它面向学生提供沉浸式听力练习，面向教师提供可维护、可统计、可推荐的教学材料。

在当前系统中，资源库对应关系如下：

| 资源库概念 | 当前项目落地 | 说明 |
| --- | --- | --- |
| 情境主题 | `materials.title` | 如学术讲座、商务谈判、会议交流、课程讨论 |
| 情境文本 | `materials.transcript` | 听力原文或脚本 |
| 情境音频 | `audio_assets` + `materials.audioId` | 已上传或外部生成的音频资源 |
| 情境难度 | `materials.level`、`questions.difficulty` | 用于推荐和能力评估 |
| 任务题目 | `questions` | 听后理解题、细节题、推理题等 |
| 选项与答案 | `question_options`、`questions.correctKey` | 选择题结构 |
| 学习行为 | `attempts`、`attempt_answers` | 学生练习记录与答题明细 |
| 能力状态 | `students.theta`、`student_ability_state` | 个性化推荐和学习画像 |

## 3. VR 虚拟场景设计原则

本项目后端不直接渲染 VR 画面，但需要为前端、小程序或后续 VR 客户端提供清晰的场景资源组织方式。VR 场景开发应遵循以下原则：

1. 教学目标优先：场景不是装饰，而是为了帮助学生理解听力语境、角色关系和交际目的。
2. 轻量化接入：后端以结构化材料、音频和题目为核心，VR 前端可根据场景标签和材料内容进行渲染。
3. 可复用资源：同一类场景可复用背景、角色、道具和交互模板，只替换文本、音频和任务。
4. 难度可控：场景材料必须绑定难度等级，便于系统根据学生能力值推荐。
5. 可统计闭环：学生在 VR 或普通听力界面中的练习结果都应回写到统一练习记录中。

## 4. 场景分类设计

### 4.1 学术讲座场景

学术讲座场景面向高校课堂、专题讲座、学术报告和课程说明等听力任务。该类场景通常语速相对稳定，信息密度较高，强调主旨理解、细节捕捉、逻辑关系和观点判断。

典型场景包括：

- 大学课堂导入讲座。
- 教授专题报告。
- 学术会议短报告。
- 课程安排与作业说明。
- 实验流程或研究方法介绍。

推荐 VR 场景元素：

- 场景背景：阶梯教室、报告厅、研讨室、实验室。
- 角色对象：主讲教师、学生听众、主持人。
- 关键道具：投影屏幕、白板、讲台、笔记本、图表。
- 交互节点：开始播放、暂停回听、查看题目、提交答案、查看解析。

材料设计要点：

- 文本结构应具有明确开头、主体和结论。
- 题目覆盖主旨题、细节题、推理题和态度题。
- 难度可通过专业词汇、句子长度、信息密度和语速进行控制。
- 适合与 `materials.level` 和 `questions.difficulty` 建立 1 到 10 的难度映射。

### 4.2 商务谈判场景

商务谈判场景面向商务会议、客户沟通、价格协商、项目推进和跨文化交流等听力任务。该类场景更强调角色关系、意图识别、礼貌表达、让步策略和关键信息提取。

典型场景包括：

- 客户需求沟通。
- 产品报价谈判。
- 合同条款讨论。
- 项目进度会议。
- 售后问题协商。

推荐 VR 场景元素：

- 场景背景：会议室、办公室、展会洽谈区、线上会议界面。
- 角色对象：销售经理、客户代表、项目负责人、翻译或助理。
- 关键道具：合同、报价单、产品样机、会议屏幕。
- 交互节点：选择谈判意图、识别关键信息、判断说话人态度、完成听后任务。

材料设计要点：

- 对话应体现多轮交流和信息推进。
- 题目应关注价格、时间、条件、让步、异议和最终结论。
- 可通过口音、语速、隐含表达、商务术语提升难度。
- 可结合错题复练功能帮助学生反复理解语用意图。

## 5. VR 场景资源结构

建议每个 VR 场景以一个材料为最小教学单元，前端或 VR 客户端可在现有材料结构外扩展场景配置。

推荐资源结构如下：

```json
{
  "sceneCode": "academic_lecture_001",
  "sceneType": "ACADEMIC_LECTURE",
  "title": "A Short Lecture on Renewable Energy",
  "level": 6.5,
  "materialId": 101,
  "audioId": 301,
  "environment": {
    "background": "lecture_hall",
    "characters": ["professor", "students"],
    "props": ["podium", "screen", "slides"]
  },
  "learningGoals": [
    "identify main idea",
    "capture supporting details",
    "infer speaker attitude"
  ],
  "interactionMode": "listen_then_answer"
}
```

当前后端已有材料、音频、题目和练习记录能力；如需支持上述 VR 元数据，可后续新增 `scene_type`、`scene_code`、`scene_config`、`learning_goals` 等字段，或建立独立的 `scene_resources` 表与 `materials` 表关联。

## 6. 场景开发流程

### 6.1 场景策划

教师或内容设计人员先确定场景类型、教学目标、难度等级和学生能力层级。例如，面向中高阶学生设计“商务报价谈判”，目标是训练学生识别报价、交付时间和让步条件。

### 6.2 文本设计

文本可由教师人工编写，也可由 Seq2Seq 或大语言模型辅助生成。生成后必须经过人工审核，确保语言自然、难度适中、信息点清晰，并符合课程目标。

### 6.3 音频制作

需求中提到 WaveNet 语音合成，其目标是将情境文本转化为自然语音。本项目当前采用直接给定音频的方式，即由教师或资源制作人员上传已有音频，后端通过 `/api/audio/register` 登记音频元数据，再通过 `/api/audio/bindMaterial` 绑定到材料。

该方式与 WaveNet 的关系可以理解为：

- WaveNet 是可选的音频生产技术。
- 本系统的 `audio_assets` 是音频接入层。
- 无论音频来自真人录制、WaveNet 合成、第三方 TTS，还是教师上传，都可以通过统一音频登记流程进入系统。

### 6.4 题目设计

每个材料需设计若干题目，题型以选择题为主，题目难度应与材料难度协调。题目数据最终写入 `questions` 和 `question_options`，并通过 `correctKey` 标记标准答案。

### 6.5 材料入库

通过 `POST /api/material/upload` 创建材料及题目，通过 `POST /api/audio/register` 和 `POST /api/audio/bindMaterial` 接入音频资源。材料启用后，学生端即可通过获取练习、推荐练习或指定材料练习接口访问。

### 6.6 学习与反馈

学生完成听力练习后，系统通过 `/practice/submit` 记录练习行为，并调用能力评估模块更新能力值。教师可在管理端通过统计接口查看学习表现。

## 7. 与后端接口的对应关系

| 开发步骤 | 后端接口 | 说明 |
| --- | --- | --- |
| 登记音频 | `POST /api/audio/register` | 保存音频路径、类型、大小、时长等元数据 |
| 创建材料 | `POST /api/material/upload` | 写入材料、题目和选项 |
| 绑定音频 | `POST /api/audio/bindMaterial` | 将音频资源绑定到材料 |
| 启用材料 | `PUT /api/material/activate/{id}` | 将材料设为可练习 |
| 获取练习 | `GET /api/material/get-practice` | 学生获取练习材料 |
| 获取推荐 | `GET /practice/get-recommend` | 根据能力值推荐材料 |
| 提交答案 | `POST /practice/submit` | 记录练习并更新能力 |
| 查看统计 | `GET /api/admin/leaderboard` 等 | 教师查看练习效果 |

## 8. 数据扩展建议

为更完整支持 VR 场景，可在现有材料库基础上扩展以下字段或表：

| 字段/表 | 类型建议 | 说明 |
| --- | --- | --- |
| `materials.scene_type` | varchar | 场景类型，如 `ACADEMIC_LECTURE`、`BUSINESS_NEGOTIATION` |
| `materials.scene_tags` | json/text | 场景标签，如课堂、会议、报价、让步 |
| `materials.learning_goals` | json/text | 学习目标 |
| `materials.scene_config` | json/text | VR 背景、角色、道具、交互点配置 |
| `scene_assets` | table | 管理 VR 背景、角色模型、贴图等资源 |
| `scene_interactions` | table | 管理可点击节点、字幕节点、任务触发点 |

上述扩展不会破坏当前材料、练习和推荐逻辑。推荐模块仍可基于 `level` 和学生 `theta` 工作，VR 客户端只需额外读取场景配置即可渲染更沉浸的界面。

## 9. 质量标准

1. 场景目标明确：每个场景至少对应一个听力训练目标。
2. 音频与文本一致：音频内容应与 `transcript` 保持一致。
3. 难度标注合理：材料难度和题目难度应使用统一量表。
4. 题目覆盖充分：每个材料应包含主旨、细节、推理等不同层次题目。
5. 资源可追踪：材料、音频、题目、练习记录之间必须能通过 ID 关联。
6. 可推荐：启用材料必须具备难度值，便于智能推荐模块使用。
7. 可复练：练习记录需保存学生选项，支持复练时展示上次选择。

## 10. 示例场景

### 10.1 学术讲座示例

场景名称：A Lecture on Urban Transportation

场景说明：学生进入虚拟报告厅，听教授介绍城市交通规划中的公共交通、拥堵管理和环境影响。听后完成 5 道选择题。

资源映射：

- `materials.title`：A Lecture on Urban Transportation
- `materials.level`：6.0
- `materials.transcript`：讲座文本
- `audio_assets.local_path`：讲座音频路径
- `questions`：主旨题、细节题、推理题、态度题、总结题

### 10.2 商务谈判示例

场景名称：Negotiating a Product Delivery Schedule

场景说明：学生进入虚拟会议室，听供应商与客户讨论产品交付周期、价格调整和售后支持。听后判断双方达成的一致意见。

资源映射：

- `materials.title`：Negotiating a Product Delivery Schedule
- `materials.level`：7.0
- `materials.transcript`：商务谈判对话文本
- `audio_assets.local_path`：谈判音频路径
- `questions`：价格题、时间题、条件题、意图题、结论题

## 11. 总结

本项目中的智能情境资源库以听力材料库为核心，通过材料、音频、题目、难度、练习记录和能力状态构成完整学习闭环。VR 虚拟场景开发可在现有后端能力之上扩展场景元数据和前端渲染能力，使“学术讲座”和“商务谈判”等情境从普通听力材料升级为具备场景感、任务感和反馈闭环的沉浸式学习资源。

当前系统虽然未直接集成 WaveNet 语音合成，但已经提供稳定的音频接入和材料绑定机制，能够兼容真人录制音频、外部合成音频以及未来接入的神经语音合成服务。
